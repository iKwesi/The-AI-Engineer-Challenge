### Detailed Error Handling Requirements
**Specific Error Scenarios That Must Be Handled**:

1. **API Key Validation Errors**:
   - Empty API key: Display "API key is required" message
   - Invalid format: Display "API key must start with 'sk-' and be at least 20 characters" message
   - Invalid key during API call: Display "Invalid API key. Please check your key and try again" message

2. **Network and API Errors**:
   - Network timeout: Display "Request timed out. Please check your connection and try again" message
   - API rate limit: Display "Rate limit exceeded. Please wait a moment and try again" message
   - Server error (5xx): Display "Server error occurred. Please try again later" message
   - Malformed response: Display "Unexpected response format. Please try again" message

3. **Form Validation Errors**:
   - Empty message: Display "Please enter a message" message
   - Message too long: Display "Message exceeds maximum length of 4000 characters" message
   - Special character handling: Must handle all Unicode characters appropriately

4. **Streaming Response Errors**:
   - Stream interruption: Display "Connection interrupted. Click to retry" with retry button
   - Partial response: Display "Response incomplete. Click to retry" with retry button
   - Stream timeout: Display "Response timed out. Click to retry" with retry button

**Error Display Requirements**:
- All errors must use consistent styling (red border, error icon, clear message)
- Error messages must be accessible to screen readers (aria-live="polite")
- Errors must be clearable (auto-clear on successful action or manual dismiss)
- Error state must not break component functionality
- All error messages must be user-friendly and actionable

### Detailed Rollback Procedures

**Rollback Trigger Conditions**:
- Any test failure that cannot be resolved within 30 minutes
- Performance degradation exceeding 20% of baseline
- Breaking changes to existing functionality
- Memory leaks or stability issues
- Accessibility compliance failures

**Rollback Procedure Steps**:
1. **Immediate Rollback** (must complete within 5 minutes):
   - Stop development and document issue in Change Log
   - Revert to last known good commit using git
   - Remove any new files created during development
   - Restore any modified files to previous state

2. **Rollback Validation Checklist**:
   - [ ] All existing tests passing (0 failures)
   - [ ] Application builds without errors
   - [ ] Application starts and loads correctly
   - [ ] All existing functionality works as before
   - [ ] No new files or dependencies left behind
   - [ ] Performance matches pre-development baseline

3. **Post-Rollback Actions**:
   - Document rollback reason in story Change Log
   - Update story status to "Blocked - Rollback Required"
   - Schedule story refinement session to address blocking issues
   - Notify PO and team of rollback and next steps

**Rollback Testing Requirements**:
